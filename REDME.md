# Cinema

Cinema — учебное клиент-серверное приложение онлайн-кинотеатра
для домашних заданий по курсу SRE.

Приложение позволяет управлять каталогом фильмов и воспроизводить
видео по прямой HTTP/HTTPS-ссылке.

## Возможности

- Создание фильма.
- Просмотр каталога с постраничной навигацией.
- Получение отдельного фильма.
- Редактирование фильма.
- Удаление фильма.
- Воспроизведение видео в браузере.
- Проверка состояния HTTP-процесса и доступности БД.

## Стек

- Backend: Go, стандартная библиотека net/http.
- PostgreSQL-драйвер: pgx v5.7.6.
- Frontend: HTML, CSS, JavaScript.
- База данных: PostgreSQL 17.
- Окружение: Docker Compose.
- Взаимодействие frontend и backend: HTTP/REST, JSON.

## Архитектура

Браузер получает frontend от Go-сервера.

JavaScript обращается к REST API того же сервера.
Backend проверяет данные и выполняет SQL-запросы к PostgreSQL.

Каталог хранится в PostgreSQL.
Видеофайлы находятся на внешнем HTTP-сервере.
Браузер загружает их напрямую по video_url.

Frontend и SQL-миграции встраиваются в Go-бинарный файл
при помощи go:embed.

## Подготовка

Все команды выполняются из корня проекта.

На этом Mac рабочий репозиторий находится в `/Users/tekha/cinema`:

```bash
cd /Users/tekha/cinema
```

После создания исходных файлов:

```bash
go mod tidy
gofmt -w cmd internal migrations web
go test ./...
go vet ./...
```

go mod tidy создаёт go.sum и дополняет go.mod.
Оба файла нужно хранить в Git и включить в архив решения.

Тесты проверяют валидацию данных.
Они не являются интеграционной проверкой PostgreSQL.

Создать локальную конфигурацию:

```bash
cp -n .env.example .env
```

При необходимости изменить значения в .env.

## Запуск

Нужен установленный и запущенный Docker с Docker Compose v2.
Для первого запуска после создания `.env`:

```bash
docker compose config --quiet
docker compose up --build -d
docker compose ps -a
```

Compose сначала ждёт готовности PostgreSQL, затем выполняет сервис
`migrate` и только после его успешного завершения запускает `app`.
`Exited (0)` у `migrate` означает успешное выполнение миграций.
Сервисы используют один образ; его собирает сервис `app`.

Те же этапы можно выполнить отдельно.

Собрать образ:

```bash
docker compose build app
```

Запустить PostgreSQL:

```bash
docker compose up -d db
```

Применить миграции отдельным процессом:

```bash
docker compose run --rm migrate
```

Продолжать запуск следует только после успешного завершения миграций.

Запустить HTTP-приложение из собранного образа:

```bash
docker compose up -d --no-build app
```

Открыть:

http://localhost:8080

При изменении PORT в .env использовать выбранный порт.

Каталог после первого запуска пуст.

## Работа с интерфейсом

1. Ввести название, описание, год и прямую ссылку на видео.
2. Нажать «Сохранить».
3. Проверить появление фильма в каталоге.
4. Нажать «Изменить» для редактирования.
5. Нажать «Смотреть», затем кнопку воспроизведения плеера.
6. Нажать «Удалить» для удаления записи.

video_url должен вести на видеофайл, например MP4.
Ссылка на страницу YouTube или другого сайта с плеером не подходит.

Для проверки плеера можно использовать демонстрационное видео:

https://developer.mozilla.org/shared-assets/videos/flower.mp4

Доступность внешнего источника и поддержка кодека проверяются браузером.
Backend проверяет формат URL, но не скачивает видео.

## REST API

| Метод | Путь | Результат |
|---|---|---|
| GET | /api/movies | Список фильмов |
| GET | /api/movies/{id} | Один фильм |
| POST | /api/movies | Создание |
| PUT | /api/movies/{id} | Обновление |
| DELETE | /api/movies/{id} | Удаление |
| GET | /healthz | Проверка HTTP-процесса |
| GET | /readyz | Проверка БД и таблицы movies |

GET /api/movies принимает параметры:

- limit: от 1 до 100, по умолчанию 12;
- offset: от 0 до 1000000, по умолчанию 0.

PUT заменяет все редактируемые поля.
Название, год и ссылка обязательны.
Описание можно передать пустой строкой.

Пример тела POST и PUT:

```json
{
  "title": "Демонстрационный фильм",
  "description": "Видео для проверки приложения",
  "release_year": 2024,
  "video_url": "https://developer.mozilla.org/shared-assets/videos/flower.mp4"
}
```

Основные коды ответа:

- 200 — успешное чтение или обновление.
- 201 — фильм создан.
- 204 — фильм удалён.
- 400 — некорректный JSON, ID или значения полей.
- 404 — фильм не найден.
- 413 — превышено ограничение тела запроса.
- 415 — требуется Content-Type: application/json.
- 500 — внутренняя ошибка.
- 503 — readiness-проверка не прошла.

## Ручная проверка API

Проверить состояние:

```bash
curl -i http://localhost:8080/healthz
curl -i http://localhost:8080/readyz
```

Ожидается HTTP 200.

Создать фильм:

```bash
curl -i -X POST http://localhost:8080/api/movies \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Тестовый фильм",
    "description": "Проверка CRUD",
    "release_year": 2024,
    "video_url": "https://developer.mozilla.org/shared-assets/videos/flower.mp4"
  }'
```

Ожидается HTTP 201 и JSON созданной записи.

Скопировать фактический id из ответа в переменную.
Ниже 1 — пример; идентификатор может отличаться:

```bash
MOVIE_ID=1
```

Получить список и запись:

```bash
curl -i 'http://localhost:8080/api/movies?limit=12&offset=0'
curl -i "http://localhost:8080/api/movies/$MOVIE_ID"
```

Изменить фильм:

```bash
curl -i -X PUT "http://localhost:8080/api/movies/$MOVIE_ID" \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Обновлённый фильм",
    "description": "Изменённое описание",
    "release_year": 2025,
    "video_url": "https://developer.mozilla.org/shared-assets/videos/flower.mp4"
  }'
```

Ожидается HTTP 200 с изменёнными полями.

Проверить сохранность данных после пересоздания контейнеров:

```bash
docker compose down
docker compose up -d
```

После готовности приложения:

```bash
curl -i "http://localhost:8080/api/movies/$MOVIE_ID"
```

Ожидается сохранённая обновлённая запись.
Команда down без -v сохраняет volume PostgreSQL.

Удалить фильм:

```bash
curl -i -X DELETE "http://localhost:8080/api/movies/$MOVIE_ID"
curl -i "http://localhost:8080/api/movies/$MOVIE_ID"
```

Ожидаются соответственно HTTP 204 и HTTP 404.

Проверить валидацию:

```bash
curl -i -X POST http://localhost:8080/api/movies \
  -H 'Content-Type: application/json' \
  -d '{}'
```

Ожидается HTTP 400.

## Конфигурация

| Переменная | Назначение |
|---|---|
| APP_IMAGE | Тег образа приложения для Compose |
| PORT | Порт HTTP-сервера |
| LOG_LEVEL | Уровень логирования |
| DB_MAX_CONNS | Максимальное число соединений одного процесса с БД |
| DATABASE_URL | Строка подключения приложения к PostgreSQL |
| POSTGRES_DB | Имя БД при первоначальной инициализации |
| POSTGRES_USER | Пользователь при первоначальной инициализации |
| POSTGRES_PASSWORD | Пароль при первоначальной инициализации |

.env не включается в Git и архив.

Программа получает настройки через окружение.
Файл .env читает Docker Compose.

POSTGRES_* не изменяют уже инициализированную БД.
Если volume существует, изменение этих переменных не обновит
автоматически пользователя, пароль и имя БД.

docker compose logs -f app

## Миграции

```bash
docker compose run --rm migrate
```

Выполненные миграции учитываются в schema_migrations.

Применённые SQL-файлы не редактируются.
Для изменения схемы добавляется новый файл с очередным номером.

Механизм поддерживает последовательные транзакционные миграции.
Автоматические down-миграции не реализованы.

## Если тесты не запускаются

`[setup failed]` означает ошибку подготовки пакета до выполнения тестов.
Если вывод содержит `missing go.sum entry`, выполни из корня репозитория:

```bash
go mod tidy
go test -count=1 -v -run '^TestInputValidate$' ./internal/movie
go test -race -count=1 ./...
```

`go mod tidy` загружает зависимости и формирует контрольные суммы.
В репозиторий нужно включить обновлённые `go.mod` и `go.sum`.
Тесты запускаются для пакета, а не отдельного файла movie_test.go.
Для работы зелёной кнопки редактора путь модуля должен соответствовать
`github.com/Tekha03/cinema`, а файлы должны быть сохранены.

## Новая версия

1. Изменить код.
2. Выполнить проверки.
3. Зафиксировать изменения в Git.
4. Назначить новый APP_IMAGE, например cinema:0.1.1.
5. Собрать образ.
6. Применить миграции из этого образа.
7. Запустить приложение с --no-build.

Тег опубликованного релиза не следует использовать для другого образа.
Для строгой фиксации контейнерных артефактов используют digest.

Откат приложения не означает автоматического отката схемы БД:
совместимость миграций необходимо учитывать отдельно.

## Остановка

```bash
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume.

## Ограничения учебной версии

- Нет регистрации и разграничения прав.
- Каталог доступен для изменения любому посетителю приложения.
- Нет загрузки, перекодирования и хранения видеофайлов.
- Нет адаптивного стриминга HLS/DASH.
- Доступность внешнего видео не проверяется backend.
- При одновременном редактировании одной записи сохраняется
  последнее успешно выполненное обновление.
- Балансировщик и несколько реплик пока не развёрнуты.
